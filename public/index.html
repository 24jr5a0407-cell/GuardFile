Security Architecture & Threat Defense Matrix

Every defense implemented in TrustVault mapped against attack vectors and automated verification.

Vector: IDOR / Broken Object Authorization Mitigated

Attack: Tampering with document UUID in /api/documents/:id/download to access other users' confidential documents.

Zero-Trust Defense: Real-time database ACL lookup on every single request. Lack of unrevoked grant blocks with 403 Forbidden and writes READ_DENIED with client IP to audit trail.

Vector: Stale Session / Instant Revocation Window Mitigated

Attack: User accesses file after owner clicks "Revoke", relying on cached permissions or signed URLs.

Zero-Trust Defense: No file permission is ever stored in JWT. Revocation updates is_revoked = TRUE in DB, instantly blocking requests in <1 millisecond.

Vector: MIME-Type & Magic Byte Spoofing Mitigated

Attack: Renaming executable malicious.exe to contract.pdf to bypass extension filter.

Zero-Trust Defense: Server-side magic bytes validation directly inspects header bytes (%PDF-, PNG magic, MZ executable headers) before storage.

Vector: Audit Trail Tampering Mitigated

Attack: Insider or compromised admin alters or deletes audit logs to hide an unauthorized download.

Zero-Trust Defense: PostgreSQL database trigger blocks UPDATE/DELETE with exception. SHA-256 cryptographic hash chaining invalidates the entire ledger if a single bit is changed.

TrustVault Terms of Service & Security Charter

1. Zero-Trust Authorization Model

Every file access, download, view, and modification request is dynamically authenticated and authorized against the database at the time of execution. No permission is cached or assumed from UI routes or tokens.

2. Immutable Cryptographic Audit Ledger

All platform interactions—including uploads, downloads, authorization checks, permission revocations, and refused access attempts—are irreversibly logged in a cryptographically chained SHA-256 ledger. Audit entries cannot be altered, updated, or deleted.

3. Immediate Access Revocation Standard

When a document owner or administrator revokes access for any user, access terminates instantaneously in under one millisecond. Any previously held access tokens or sessions cannot reach revoked resources.

4. Credential Uniqueness & Anti-Collision Policy

All registered emails and phone numbers must be unique across the entire platform. Credential sharing and secondary account reuse are strictly prevented to maintain non-repudiation and forensic accountability.

5. Data Privacy & Confidentiality

Files are stored in physically isolated storage outside the public web root. Documents are validated for magic byte signatures and content checksums to defend against path traversal, tampering, and malware delivery.
